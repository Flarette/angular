# No-op binding on a marker element

A template puts a binding on `<ng-container>` or `<ng-template>` that has no effect, because neither element renders a DOM element.

In development mode, Angular reports the following bindings when it creates a template:

- Class and style bindings, such as `[class.active]` or `[style]`, that no directive input takes over.
- Event bindings, such as `(click)`, that no directive output claims and that have no global target such as `window:` or `document:`.

```angular-ts
import {Component, signal} from '@angular/core';

@Component({
  selector: 'app-item',
  // NG0319: neither binding has an effect, because <ng-container> doesn't render an element.
  template: `
    <ng-container [class.active]="active()" (click)="select()">
      <span>{{ label }}</span>
    </ng-container>
  `,
})
export class Item {
  label = 'Item';
  active = signal(false);

  select() {
    this.active.set(true);
  }
}
```

Angular logs this error with `console.error`. It throws instead when [`errorOnUnknownProperties`](api/core/testing/TestModuleMetadata#errorOnUnknownProperties) is enabled in tests. Host bindings of directives aren't reported, because a directive can also be applied to elements where those bindings work.

## Debugging the error

Use the binding and the component name in the error message to find the template. Then pick the fix that matches what the binding was meant to do:

- **Style or listen to the content**: move the binding to an element inside the marker, or replace the marker with an element.
- **Set a directive input or listen to a directive output**: add the directive to the component's `imports`.
- **Nothing reads the binding**: remove it.

With [`strictTemplates`](tools/cli/template-typecheck#strict-mode), the compiler reports these bindings at build time as [NG8031](errors/NG8031), along with other bindings and attributes that marker elements drop.
