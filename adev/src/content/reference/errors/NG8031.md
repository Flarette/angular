# No-op binding on a marker element

A template puts a binding or an attribute on `<ng-container>`, `<ng-template>`, or `<ng-content>` that can never take effect.

None of these elements renders a DOM element. `<ng-container>` and `<ng-template>` leave at most a comment in the DOM, and Angular replaces `<ng-content>` with projected content. A class, style, attribute, or event binding on them has nothing to apply to, so Angular drops it.

```angular-ts
import {Component, signal} from '@angular/core';

@Component({
  selector: 'app-item',
  // NG8031: neither binding has an effect, because <ng-container> doesn't render an element.
  template: `
    <ng-container [class.active]="active()" (click)="select()">
      <span>{{ label }}</span>
    </ng-container>
  `,
})
export class Item {
  label = 'Item';
  active = signal(false);

  select() {
    this.active.set(true);
  }
}
```

The compiler reports the following on these elements:

- Class, style, `attr.`, and `animate.` bindings that no directive input claims.
- Event bindings, including `(animate.enter)` and `(animate.leave)`, that no directive output claims and that have no global target such as `window:` or `document:`.
- Static attributes that nothing reads: no directive matched the element, no specific content projection slot selects it, and Angular doesn't read the attribute itself, as it does with `i18n`, `ngNonBindable`, `ngProjectAs`, and `select` on `<ng-content>`.
- Every binding on `<ng-content>`, which Angular never evaluates.
- Components whose selector matches `<ng-container>` or `<ng-template>`, which can't host a component.

Bindings that a directive on the element claims aren't reported, and neither are host bindings of directives.

## Debugging the error

Pick the fix that matches what the binding was meant to do:

- **Style or listen to the content**: move the binding to an element inside the marker, or replace the marker with an element.

  ```angular-ts
  @Component({
    selector: 'app-item',
    template: `<span [class.active]="active()" (click)="select()">{{ label }}</span>`,
  })
  export class Item {
    label = 'Item';
    active = signal(false);

    select() {
      this.active.set(true);
    }
  }
  ```

- **Set a directive input or listen to a directive output**: add the directive to the component's `imports`. For example, `[ngTemplateOutlet]` needs `NgTemplateOutlet`.
- **Select a content projection slot**: give the marker an `ngProjectAs` attribute that matches the slot's selector. For details, see [Aliasing content for projection](guide/components/content-projection#aliasing-content-for-projection).
- **Nothing reads the binding**: remove it.

## Configuring the diagnostic

NG8031 needs [`strictTemplates`](tools/cli/template-typecheck#strict-mode) and is an error by default. To report it as a warning while you migrate, or to turn it off, set `noOpMarkerBinding` in the `extendedDiagnostics` section of `tsconfig.json`:

```json
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "noOpMarkerBinding": "warning"
      }
    }
  }
}
```

The value can be `"error"`, `"warning"`, or `"suppress"`.
