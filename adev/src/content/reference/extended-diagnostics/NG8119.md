# A directive output named `class` claims the `(class)` binding.

This diagnostic detects a `(class)` binding on an element where a directive declares an output named `class`.

<!-- prettier-ignore -->
```angular-ts
import {Component, Directive, output} from '@angular/core';
import {cn} from './cn';

@Directive({selector: '[highlight]'})
class Highlight {
  readonly changed = output<string>({alias: 'class'});
}

@Component({
  imports: [Highlight],
  template: `<div highlight class="px-2" (class)="cn($event)"></div>`,
})
class MyComponent {
  protected readonly cn = cn;
}
```

## What's wrong with that?

A `(class)` binding on an element receives the element's classes from all sources and returns the classes the element should have.
When a directive on the element declares an output named `class`, the binding listens to that output instead, so the element's classes aren't resolved.

## What should I do instead?

Rename the directive's output so that the `(class)` binding resolves the element's classes.

```angular-ts
import {Component, Directive, output} from '@angular/core';
import {cn} from './cn';

@Directive({selector: '[highlight]'})
class Highlight {
  readonly changed = output<string>({alias: 'highlightChange'});
}

@Component({
  imports: [Highlight],
  template: `<div highlight class="px-2" (class)="cn($event)"></div>`,
})
class MyComponent {
  protected readonly cn = cn;
}
```

## Configuration requirements

[`strictTemplates`](tools/cli/template-typecheck#strict-mode) must be enabled for any extended diagnostic to emit.
`classResolverShadowedByOutput` has no additional requirements beyond `strictTemplates`.

## What if I can't avoid this?

This diagnostic can be disabled by editing the project's `tsconfig.json` file:

```json
{
  "angularCompilerOptions": {
    "extendedDiagnostics": {
      "checks": {
        "classResolverShadowedByOutput": "suppress"
      }
    }
  }
}
```

See [extended diagnostic configuration](extended-diagnostics#configuration) for more info.
